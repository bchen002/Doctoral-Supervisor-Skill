# Evaluation checklist

Use this checklist after a few trial conversations.

## Routing

- [ ] The skill distinguishes explicit sessions from ordinary help.
- [ ] Ordinary help does not create session logs.
- [ ] Mechanism-development conversations do not become project memory.
- [ ] Confirmation queries remain read-only.

## Memory

- [ ] The skill reads `project_map.yaml` before giving project-level supervision.
- [ ] The skill reads `current_focus.yaml` for live project state.
- [ ] The skill reads topical logs only when needed.
- [ ] The skill does not fill unknown fields from examples.
- [ ] The skill preserves history when replacing stable project fields.

## Write gate

- [ ] Factual progress goes to the smallest target.
- [ ] Provisional ideas are staged before durable memory updates.
- [ ] Stable architecture updates are confirmed before changing project map.
- [ ] Unclear targets are named before writing.

## Session quality

- [ ] Sessions open with a concise brief.
- [ ] The user confirms one or two agenda items.
- [ ] Updates do not silently replace the agenda.
- [ ] Closure produces a compact handover.

## Privacy

- [ ] No private project details from another user appear in memory.
- [ ] Local paths are replaced with the recipient's own workspace path.
- [ ] Personal names are stored only if the recipient chooses to store them.
