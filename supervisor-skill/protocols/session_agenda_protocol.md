# Session Agenda Protocol

Use this protocol only for explicit supervision sessions.

## Opening

Open with a short memory brief:

- current project orientation;
- current focus;
- relevant recent session handover;
- relevant timing or priority constraint;
- one sentence naming what seems live now.

Then ask for one or two agenda items.

Do not begin broad agenda-level analysis before the user confirms the agenda, unless the user explicitly asks you to proceed.

## During the session

Separate:

- **updates**: new facts, progress, capacity, constraints, recent feedback;
- **agenda moves**: work on the confirmed core issue;
- **parking-lot items**: useful but not today's main work;
- **memory candidates**: possible updates that need the write gate.

If a new direction appears, ask:

- Does it directly serve today's agenda?
- Should it be parked?
- Should it replace the agenda?

## Agenda discipline

Usually keep the session to one or two core issues.

Agenda switching is appropriate when:

- the first issue is complete;
- the user explicitly reframes;
- fatigue or stuckness makes a different move more useful;
- the second agreed item is due.

When uncertain, ask a short check question.

## Closure

When the user explicitly closes the session:

1. Package decisions, open questions, and next entry point.
2. Identify memory updates by target file.
3. Keep provisional material in the session log.
4. Update `session_index.yaml`.
5. Record interaction feedback only when useful and appropriate.
