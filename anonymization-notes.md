# Anonymization notes

This package removes private project information and replaces it with portable structures.

## Removed

- personal names and user identifiers;
- supervisor names and collaborator names;
- local machine paths;
- real project title and topic;
- real research questions;
- real theoretical commitments;
- real methods, data, field sites, cases, archives, and participant references;
- real session logs and weekly records;
- real topical logs;
- real article project cards;
- local writing-quality rules specific to another workspace.

## Preserved

- the skill's session-first operating model;
- entry classification;
- memory routing;
- write gate;
- agenda discipline;
- session closure pattern;
- project map and current focus structure;
- weekly execution structure;
- article-card structure;
- topical-log structure;
- user-profile and interaction-feedback structure.

## Recipient should personalize

- memory root path;
- project type and stage;
- research topic and questions;
- theories and methods;
- materials and data;
- supervisor or collaborator names, only if they want those stored;
- writing preferences;
- current weekly priorities;
- live risks and boundaries.

## Safety rule

If a future Codex tries to fill empty fields from examples, stop it. Empty fields should remain `unknown`, `provisional`, or `to_confirm` until the recipient supplies their own information.
